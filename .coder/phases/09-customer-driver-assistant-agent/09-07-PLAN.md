<objective>
## Goal
Serve the whole Next.js app under a `/agentic-travels` URL prefix instead of bare root, mirroring `mastech-agentic-commerce`'s `basePath` convention exactly, with a redirect from `/` to `/agentic-travels` and every hardcoded client-side `/api/...` fetch call updated to stay correct under the prefix.

## Purpose
The sibling repo `mastech-agentic-commerce` serves its storefront under `/agentic-commerce` (via `next.config.js`'s `basePath` + a root-redirect rule) so it can co-exist with other services on one host. This project needs the same convention (`/agentic-travels`) before any shared-host deployment story is decided — confirmed directly against commerce's `next.config.js`, `lib/basePath.ts`, and `app/layout.tsx`, so this plan replicates a working pattern rather than inventing one.

## Output
- `next.config.js`: `basePath: '/agentic-travels'` + a `redirects()` rule bouncing `/` to `/agentic-travels`.
- `lib/basePath.ts`: new file exporting `BASE_PATH = '/agentic-travels'`, matching commerce's file shape exactly.
- Every literal `fetch('/api/...')` / `fetch(\`/api/...\`)` call site updated to prefix with `BASE_PATH` so client-side requests resolve correctly once the app is mounted under the prefix (Next's `basePath` auto-prefixes `<Link>`/`router.push`, never `fetch()` string literals).
- `app/layout.tsx`'s `<ClerkProvider>` given `afterSignOutUrl={BASE_PATH}` (matching commerce) — sign-in/up stay as this project's existing dedicated `/sign-in`/`/sign-up` pages (unlike commerce's modal-based flow), so those routes get updated via `NEXT_PUBLIC_CLERK_SIGN_IN_URL`/`_UP_URL` env values instead, not `ClerkProvider` fallback-redirect props.
- `.env.local.example`: `NEXT_PUBLIC_CLERK_SIGN_IN_URL`/`NEXT_PUBLIC_CLERK_SIGN_UP_URL` updated to `/agentic-travels/sign-in` / `/agentic-travels/sign-up`.
</objective>

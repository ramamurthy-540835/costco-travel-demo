<objective>
## Goal
Upgrade the customer assistant's chat experience: extend `search_inventory` with a hybrid (structured filter + thesaurus/synonym) vehicle-class filter, make the assistant's prose genuinely conversational, and render `search_inventory` results as real `VehicleCard`s in the chat instead of plain indicator text — mirroring `mastech-agentic-commerce`'s conversational shopping UI pattern (cards render structured data, prose stays short and refers to what's already shown).

## Purpose
09-01/09-02 shipped a functional but visually thin assistant: `search_inventory` only filters by city, and every tool result (including search matches) renders as a flat "Checking: X…/Done: X" line. This closes the gap the user flagged directly: results aren't shown "beautifully," the assistant isn't conversational, and there's no card view. AG-UI was evaluated and explicitly rejected (full multi-agent event-schema protocol, no interop need here) in favor of a tool-name-keyed renderer registry — the same underlying pattern AG-UI/Vercel AI SDK use internally, without adopting the protocol. Vector-embedding-based semantic discovery was also evaluated and deferred as separable new infrastructure (see 09-03-SUMMARY.md decision log / plan history), not part of this plan's scope.

## Output
- `search_inventory` accepts an optional `vehicleClass` filter, resolved (along with `city`) through the existing Phase 7 `resolveSynonym()` thesaurus before querying the graph
- `SYSTEM_PROMPT` instructs the model not to restate card-rendered vehicle details in prose and to keep responses short/conversational
- `components/assistant-chat.tsx` renders `search_inventory` tool_results as a horizontal strip of the existing `VehicleCard` component, while preserving the current propose_* Confirm/Cancel behavior unchanged
</objective>

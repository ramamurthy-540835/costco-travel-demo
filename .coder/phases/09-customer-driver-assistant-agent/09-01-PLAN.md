<objective>
## Goal
Stand up the Customer/Driver Assistant as its own separately-deployable Node/tsx process at `agent-service/customer-assistant/` (own port, own npm script, no coupling to the Next.js process — mirrors `agent-service/vendor-agent/`'s convention exactly) exposing a `POST /chat` SSE streaming endpoint that runs an Azure-OpenAI-backed tool-calling loop over 10 discovery-to-checkout tools (the 7 base tools from ROADMAP.md's Phase 9 scope, plus the 3 `propose_*` tools that implement the proposal→confirm gate), with Mongo-backed session state and that gate enforced server-side on every mutating tool.

**Adversarial review (round 1, 2026-09-08, 2 reviewer agents — correctness/security + feasibility/completeness):** 11 findings, all fixed in this version before APPLY — see the Decisions note in ROADMAP.md's Phase 9 section and inline callouts below. Most significant: (1) the original "7 tools" framing undercounted the 3 `propose_*` tools by omission, now reconciled; (2) `create_booking`'s confirm path had no route in this plan that could ever produce a real succeeded Stripe PaymentIntent — `POST /api/bookings` has no `dryRun` mode unlike modify/cancel — fixed by routing booking proposals through the existing `/api/payments/intent` endpoint and making payment collection an explicit 09-02 UI step, not a chat-only confirm; (3) `consumePendingProposal` semantics were unspecified for the match-then-clear race — now pinned to a single atomic `findOneAndUpdate`; (4) no env var existed for the tools to reach the Next.js app itself — added `NEXTJS_APP_URL`; (5) `AZURE_OPENAI_DEPLOYMENT_NAME` (the `model` param Azure requires) was missing from the chat-loop instructions; (6) AC-4 referenced `/addons`, which no tool in this plan calls — removed.

## Purpose
PROJECT.md's Core Value is negotiated-rate/perk integrity — every existing mutating booking route already enforces this server-side (dry-run-then-confirm, optimistic-lock CAS). This plan gives members a conversational entry point to that *same* integrity-checked path (never bypassing it), while keeping the agent process itself independently deployable/scalable/restartable from the Next.js app and the Vendor Agent, per Phase 8's established `agent-service/<name>/` pattern and the user's explicit requirement that this be a separate deployable service.

## Output
- `agent-service/customer-assistant/server.ts` — `http` server, `.env.local` loader (copied convention from vendor-agent), `POST /chat` SSE endpoint, `GET /health`
- `agent-service/customer-assistant/tools.ts` — 10 tool definitions + handlers wrapping existing routes/A2A/retrievers
- `agent-service/customer-assistant/vendor-agent-client.ts` — JSON-RPC `message/send` client to the Phase 8 Vendor Agent
- `agent-service/customer-assistant/session-store.ts` — Mongo `ConversationSession` model (conversation_id-keyed state machine + compacted history)

- `package.json` — `customer-assistant:dev` script
- `agent-service/customer-assistant/README.md` — run instructions, env vars, curl/SSE examples per tool including a proposal→confirm round-trip

## AC-1: Independently deployable process, own port, no Next.js coupling
```gherkin
Given the repo with only `npm run customer-assistant:dev` executed (no `next dev` running)
When the process starts
Then it listens on its own port (distinct from the Next.js app and the Vendor Agent), loads `.env.local` itself, and connects to real Mongo — proving it never imports Next.js runtime code or requires the Next.js process to be up
```

## AC-2: Discovery tools return real graph/Mongo-backed data
```gherkin
Given a running customer-assistant process and a `POST /chat` request with a natural-language search phrase
When the tool-calling loop resolves it to `search_inventory`/`get_quote`
Then the tool handler returns real data sourced from `lib/graph/retrievers.ts`/`lib/graph/queries.ts` and this project's existing rate logic — no fabricated/mocked tool output
```

## AC-3: Mutating tools require propose-then-confirm, enforced server-side
```gherkin
Given a conversation where the model calls `create_booking`/`modify_booking`/`cancel_booking` directly, without a prior matching `propose_*` call in this session's state machine
When the orchestration layer receives that tool call
Then it rejects the call server-side (never fires the real mutating API route) and returns a message telling the model to propose first — this is enforced by session state, not by prompting the model to behave
```

## AC-4: Mutating tool calls forward the caller's real Clerk session, never a client-supplied member ID
```gherkin
Given a `POST /chat` request carrying the caller's Clerk session token
When any tool calls this project's Next.js API routes (`POST /api/bookings`, `/modify`, `/cancel`)
Then the token is forwarded as the Cookie/Authorization header on that internal HTTP call, and the route's own Clerk auth + rate/perk recompute + optimistic-lock logic runs unmodified — the agent duplicates zero business logic
```
Note: `/addons` is not called by any tool in this plan's 10-tool set (ROADMAP's Phase 9 scope note doesn't list an addon tool) — omitted deliberately, not a gap.

## AC-5: Vendor Agent calls use the real A2A JSON-RPC surface
```gherkin
Given a tool needs vendor availability/policy/modification/cancellation data
When it executes
Then it sends a `message/send` JSON-RPC request to the Phase 8 Vendor Agent's `/a2a` endpoint (not a direct import of `policy.ts`) and handles a `failed` Task state without throwing
```

## AC-6: `create_booking` only fires after a real succeeded PaymentIntent exists, collected via a UI step — never chat-text-only
```gherkin
Given `propose_booking` has returned a Stripe PaymentIntent `client_secret` for the quoted total (created via `POST /api/payments/intent`, the same endpoint the existing checkout flow uses)
When the member has not yet completed payment through a card-collection UI (09-02's confirm card) against that `client_secret`
Then `create_booking` cannot succeed — `POST /api/bookings` requires a `paymentIntentId` whose Stripe status is `succeeded` and whose amount matches the quote exactly, and this plan adds no bypass of that check
```

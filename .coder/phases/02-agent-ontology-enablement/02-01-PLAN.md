# 02-01 — Agent-Enablement Ontology Layer

## Context
Phase 1 built the domain ontology/knowledge graph and a Thesaurus layer that only handles data-level naming variance (e.g. Payless's "Compact Plus" vs canonical "Compact"). The user asked to enrich the Vocabulary/Taxonomy/Thesaurus/Ontology/Knowledge Graph specifically so a conversational agent (assisting members with reservations/fulfillment) and fulfillment-side agents can resolve natural-language phrasing, and to check how the sibling `mastech-agentic-commerce` project handles this (read-only reference).

**Research findings (read-only, mastech-agentic-commerce):**
- Synonym handling lives as a `synonyms` list property directly on ontology nodes, queried via `toLower($keyword) IN [x IN a.synonyms | toLower(x)]` — no separate conversational-ontology doc layer or service.
- Genuinely ambiguous dimensions are resolved via an LLM tool-choice-forced classifier at runtime, not a static table.
- Fulfillment-side agent tools are gated by `check_access`/`record_audit` on every call, in their own file, with fulfillment concerns modeled as their own graph relation.
- **Confirmed gap**: zero precedent for action/intent-level paraphrase resolution ("cancel my booking", "cheapest car") — its thesaurus only covers attribute nouns. This phase pioneers that piece rather than porting it.

**Decisions (via AskUserQuestion):** inserted as new Phase 2, right after ontology/KG and before Stack Foundation; scope covers both attribute-level synonyms (ported pattern) and action/intent-level vocabulary (the new gap); ontology/KG only — no tool-calling contract yet (deferred to when the actual agents are built).

## Scope
1. Add a `synonyms` list property directly onto `VehicleClass` (9), `Perk` (8), `AddOn` (8), `MembershipTier` (3) nodes — attribute-level colloquial phrasing, ported from agentic-commerce's pattern.
2. New `Intent` node type (10 canonical conversational actions covering UC1/2/3/6 member-facing and UC4/5/7/8 fulfillment-facing) with `synonyms`, `related_uc`, `target_entity` — seeded from new `data/synthetic/agent_intents.json`.
3. New `TARGETS` edge: `(Intent)-[:TARGETS]->(entity)` so a recognized intent resolves straight to the graph entity/traversal it needs.
4. Comparative/policy phrases ("cheapest", "no deposit", "flexible cancellation") documented in `THESAURUS.md` as sort/filter directives — not modeled as new graph structure.

**Not in scope:** tool-calling contract (`check_access`/`record_audit`, typed function definitions) — deferred to the phase that builds the actual conversational/fulfillment agents.

## Acceptance criteria
- `python graph/scripts/load_seed_data.py` run twice → identical counts (idempotent)
- `python graph/scripts/verify_graph.py` → `Intent`=10, `TARGETS` edge present, `synonyms` spot-checks pass, all Phase 1 checks still pass
- Manual Cypher spot-check: "cheapest car" resolves to `VehicleClass{class_name:"Economy"}`; "cancel my booking" resolves to `Intent{intent_id:"cancel_reservation"}`
- No sibling project (`mastech-agentic-commerce`, `mastech-rental-car-management`) modified — read-only reference only

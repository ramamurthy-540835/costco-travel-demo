<objective>
## Goal
Stand up the Clerk-authenticated Playwright test infrastructure (auth fixture, folder/tag tiering, Mongo test-data fixtures, Stripe network-mock helper) so subsequent plans can write real authenticated regression specs against it, instead of hand-rolling auth/data setup per spec.

## Purpose
Per ROADMAP.md Phase 6, every authenticated flow (booking, modification, cancellation, add-ons) has only ever been checkpoint-verified by manual click-through — there is no automated coverage that can drive a signed-in session. `tests/e2e/smoke.spec.ts` says so explicitly in its own comments. This plan closes that specific gap: the fixture layer, not yet the regression specs themselves (those come in `06-02`+, once this foundation is verified working).

## Output
- `@clerk/testing` wired via a project-based Playwright `setup` project (`auth.setup.ts`), producing a reusable `storageState`.
- `tests/e2e/smoke/` and `tests/e2e/regression/` folder split (existing `smoke.spec.ts` moved, untouched in content).
- A worker-scoped Mongo client fixture + test-scoped tagged-document fixtures (`testMember`, `testBooking`) for self-seeding/self-cleaning regression tests.
- A Stripe network-mock helper (`page.route` stub for PaymentIntent creation/confirmation) for use by regression specs that need a payment step without driving the real Elements iframe.
- Updated `package.json` scripts (`test:e2e:smoke`, `test:e2e:regression`) and env var documentation.
</objective>

```gherkin
Given a Clerk test-instance user (`+clerk_test@` alias) with credentials in a gitignored `.env.test`
```

```gherkin
Given the existing unauthenticated smoke spec has moved to `tests/e2e/smoke/smoke.spec.ts`
```

```gherkin
Given a Playwright test using the `testMember` fixture
When the test runs

```

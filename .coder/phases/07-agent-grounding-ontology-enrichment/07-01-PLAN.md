<objective>
## Goal
Add a new `EquivalenceCluster` node type + `PART_OF_CLUSTER` edge to the rental knowledge graph, modeling cross-`VehicleClass` substitutability ("no exact match on Compact, what's close?") — genuinely new to this project, not an extension of the existing `PARENT_OF` taxonomy grouping — and expose it via a new `getEquivalenceCandidates()` query function.

## Purpose
Both the Phase 8 Vendor Agent and Phase 9 Customer/Driver Assistant need a "no exact match, what's close" resolution path when a member's requested vehicle class has no availability. The existing `TAXONOMY.md`/`PARENT_OF` structure groups classes into Standard/Utility/Premium for *classification*, not substitutability — Economy and Compact are siblings under "Standard" but a member who can't get an Economy car would reasonably accept a Compact, whereas nobody expects a Pickup as a substitute for a Minivan even though both roll up to different groups already. This phase's ontology work is the shared grounding layer both agents will consume before either is built (per `.coder/research/agent-service-extension.md` Part A §7's `EquivalenceCluster`/`PART_OF_CLUSTER` template, ported from `mastech-agentic-commerce` where it modeled Product substitutability for out-of-stock recovery — net-new there too, not an existing asset).

## Output
- `data/synthetic/equivalence_clusters.json` (new) — hand-curated substitution groups, one row per cluster
- `graph/scripts/load_seed_data.py` extended to seed `EquivalenceCluster` nodes + `PART_OF_CLUSTER` edges from `VehicleClass` to cluster
- `lib/graph/queries.ts` gains `getEquivalenceCandidates(className: string): Promise<VehicleClass[]>` — given a class name, returns sibling classes in the same cluster (excluding the input class itself)
- `ONTOLOGY.md`/`VOCABULARY.md` updated with the new node/edge type and the seeded cluster list
</objective>

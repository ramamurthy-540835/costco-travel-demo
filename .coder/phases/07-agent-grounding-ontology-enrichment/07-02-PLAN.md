<objective>
## Goal
Close the real gap in the existing `synonyms`-property pattern: `Location` (city) nodes have no `synonyms` at all (unlike `VehicleClass`/`Perk`/`AddOn`/`MembershipTier`, which got hand-curated dicts in Phase 2). Build a genuinely LLM-generated synonym-backfill script — mirroring `mastech-agentic-commerce`'s `backfill_synonyms.py` forced-function-call pattern, using Azure OpenAI (switched from plain OpenAI API mid-APPLY per user decision 2026-09-07 — user already provisioned Azure OpenAI credentials) — and run it against the 10 seeded cities to give `Location` real, non-hardcoded colloquial aliases (e.g. "NYC"/"the Big Apple" for New York, "Vegas" for Las Vegas).

## Purpose
Both the Phase 8 Vendor Agent and Phase 9 Customer/Driver Assistant need to resolve natural-language location phrasing ("pick up in Vegas") against the graph exactly the way they'll resolve vehicle-class/perk/addon phrasing — but today Location has no synonym data source at all, hardcoded or otherwise. This also establishes the *pattern* for future synonym backfills (new vendors' cities, new vocabulary) to run as a script rather than requiring another hand-written dict, per PROJECT.md's "generic stack" spirit and the research doc's (`agent-service-extension.md` Part A §7) explicit LLM-backfill-script template.

## Output
- `graph/scripts/backfill_synonyms.py` — new, idempotent, Azure-OpenAI-forced-tool-call synonym generator, addressable by `--labels` (defaults to `Location`), skips nodes with existing non-empty `synonyms` unless `--force`
- All 10 `Location` nodes carry a real, LLM-generated `synonyms` list
- `verify_graph.py` gains a check enforcing this
- `VOCABULARY.md`/`ONTOLOGY.md` document the new property and the backfill-script pattern
</objective>

  <files>graph/requirements.txt, .env.local.example, graph/scripts/backfill_synonyms.py</files>
  <action>
    Add `openai` to `graph/requirements.txt` (pin a current major version, e.g. `openai>=1.0,<2.0` — the `AzureOpenAI` client ships in the same package as the plain `OpenAI` client).
    Add `AZURE_OPENAI_API_KEY=`, `AZURE_OPENAI_ENDPOINT=`, `AZURE_OPENAI_DEPLOYMENT_NAME=`, `AZURE_API_VERSION=` (with a one-line comment, no real values) to `.env.local.example` — do NOT write any real key/endpoint anywhere.

    Create `graph/scripts/backfill_synonyms.py`, reusing `load_seed_data.py`'s exact `get_connection()`/`cypher()` connection pattern (same imports, same `sys.path.insert`). Implementation:
    - `argparse` CLI: `--labels` (comma-separated, default `Location`), `--force` (bool flag, default False), `--model` (default `None` — falls back to `AZURE_OPENAI_DEPLOYMENT_NAME` env var; for Azure OpenAI, `model` in the chat-completions call must be the deployment name, not a model family name like `gpt-4o-mini`).
    - `KEY_FIELD = {"Location": "city", "VehicleClass": "class_name", "Perk": "perk_id", "AddOn": "addon_id", "MembershipTier": "tier_id"}` — a small per-label map so the script generalizes beyond Location without new code later.
    - `fetch_nodes(cur, label, key_field)`: `cypher(cur, f"MATCH (n:{label}) RETURN n")` only executes — call `cur.fetchall()` afterward to get the `(raw,)` rows to parse, same as `verify_graph.py`'s `count_label`. `parse_agtype` returns the full vertex object `{"id":..., "label":..., "properties": {...}}`, NOT a flat property dict — mirror `verify_graph.py`'s `resolve_one()` pattern exactly: `props = parse_agtype(raw).get("properties", {})`, then `key_val = props.get(key_field)`, `synonyms = props.get("synonyms", [])`. Return a list of `{key_field: key_val, "synonyms": synonyms}`. Do NOT call `.get(...)` directly on the parsed vertex — the values live one level down, under `properties`.
    - `needs_backfill(node)`: `not node.get("synonyms")` — True when the property is missing or an empty list (this operates on the already-unwrapped dict returned by `fetch_nodes`, so a flat `.get()` here is correct).
    - `generate_synonyms(client, model, label, term)`: real Azure OpenAI chat completion call (`client.chat.completions.create(model=model, ...)`, where `client` is an `openai.AzureOpenAI` instance and `model` is the deployment name) with `tools=[{"type": "function", "function": {"name": "generate_synonyms", "description": "Generate 2-4 short colloquial synonyms/aliases a customer might use for this term", "parameters": {"type": "object", "properties": {"synonyms": {"type": "array", "items": {"type": "string"}, "minItems": 2, "maxItems": 4}}, "required": ["synonyms"]}}}]`, `tool_choice={"type": "function", "function": {"name": "generate_synonyms"}}` — forces structured output, mirroring commerce's `backfill_synonyms.py` pattern (same forced-tool-call shape as the plain OpenAI API — Azure OpenAI's `AzureOpenAI` client exposes an identical `chat.completions.create` surface). Parse `response.choices[0].message.tool_calls[0].function.arguments` (JSON) to get the `synonyms` list. Prompt content: e.g. `f"Term type: {label}. Term: \"{term}\". Generate short colloquial synonyms/nicknames a customer might type or say for this {label.lower()}."`
    - `main()`: reads `AZURE_OPENAI_API_KEY`/`AZURE_OPENAI_ENDPOINT`/`AZURE_OPENAI_DEPLOYMENT_NAME`/`AZURE_API_VERSION` from env (fail with a clear message — not a stack trace — if any is unset), constructs `AzureOpenAI(api_key=..., azure_endpoint=..., api_version=...)`, connects to the graph, for each `--labels` entry fetches nodes via `KEY_FIELD`, skips nodes where `needs_backfill()` is False unless `--force`, calls `generate_synonyms()` for the rest, writes back via `cypher(cur, f"MATCH (n:{label} {{{key_field}: $key}}) SET n.synonyms = $synonyms", {"key": key_val, "synonyms": synonyms})`, prints one line per node updated (`f"{label} {key_val}: {synonyms}"`) and a final count summary. The reused `get_connection()` is already autocommit (same as `load_seed_data.py`, which never calls `conn.commit()` despite hundreds of MERGEs) — do not add an explicit commit step or change autocommit behavior.
    Avoid: silently swallowing an Azure OpenAI API error per-node (let it raise — a partial backfill with a clear traceback is better than silently leaving nodes empty); do not touch `VEHICLE_CLASS_SYNONYMS`/`PERK_SYNONYMS`/`ADDON_SYNONYMS`/`MEMBERSHIP_TIER_SYNONYMS` in `load_seed_data.py` — those stay hand-curated, out of scope for this plan.

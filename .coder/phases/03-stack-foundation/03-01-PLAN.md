**Revision note (2026-08-28):** Original AC-2 assumed `clerkMiddleware()` with a matcher globally redirects unauthenticated visitors to `/sign-in`. Verified against a live checkpoint that this is false — `clerkMiddleware()` alone only attaches auth context; it does not enforce protection without an explicit `auth.protect()` call or a per-page `auth()`/`redirect()` check. Confirmed `mastech-agentic-commerce` itself uses the latter pattern (`app/user-profile/page.tsx`), not global middleware redirect. Since 03-01 is scaffold-only with no protected page yet, route-level gating is deferred to whichever Phase 4+ plan adds the first page that actually needs it — this AC now covers only that the auth plumbing works, confirmed live: `/sign-in` (200, Clerk UI present) and `/sign-up` (200) both render correctly with real keys.

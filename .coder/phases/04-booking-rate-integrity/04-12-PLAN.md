<objective>
## Goal
Enrich the checkout page with the vehicle/vendor/perk/policy details already fetched but currently dropped, add BookCars-style extras toggles (Additional Driver, Collision Damage Waiver, Roadside Assistance, GPS Navigation, Child Seat) that live-recalculate the total, and extend the existing server-side rate-integrity check in `app/api/bookings/route.ts` so the extras total is enforced, not just displayed.

## Purpose
This repo's phase is literally "Booking & Rate Integrity" — `app/api/bookings/route.ts` already recomputes `dailyRate * nights` server-side and rejects a booking if it doesn't match the Stripe-charged amount. Adding client-toggleable extras without extending that same recomputation would silently reopen the exact class of bug this phase exists to prevent (a client-controlled price nobody re-verifies). This plan makes the richer checkout UI and the integrity check land together, not as separate passes.

## Output
- Checkout page shows vehicle make/model/gearbox/seats, vendor rating/minimum_rental_days, perks, negotiated term (mileage/cancellation), fuel policy, deposit, and vendor policy (modification cutoff, no-show fee, refund days).
- Checkout form gains 5 extras toggles, each disabled+free when waived by an existing perk, otherwise togglable and reflected live in the total and in the Stripe PaymentIntent amount.
- `app/api/bookings/route.ts` recomputes the expected total including non-waived selected addons and rejects on mismatch, same as it already does for the base rate.
- `tests/e2e/smoke.spec.ts` gains 2 assertions — scoped to what's reachable without a Clerk test-auth fixture (which does not exist in this repo and is out of scope to add): the unauthenticated `/checkout` reachability check stays as-is, and the 2 new assertions target the extras-toggle price math via a small isolated unit-style check (e.g. a pure function extracted for total calculation, or an assertion against `checkout-form.tsx`'s rendered output using a mocked/authenticated Playwright storage state if one already exists elsewhere in the repo — Task 4 decides based on what it finds, but must not silently skip AC-2's e2e coverage without calling it out in the SUMMARY).
- **Search-entry gating (added post-checkpoint, same plan):** pickup/drop-off location becomes a required field on every search-entry form (hero, filters, and a new shared `SearchFormFields` component); `/search` gates on a missing `location` param instead of rendering blank/unfiltered results; the vehicle-type carousel opens a pre-filled search modal (reusing `SearchFormFields`) instead of linking directly into an ungated `/search?vehicleClass=X`; the vehicle-type dropdown's "all" sentinel and label are corrected to `'All'`/"All Vehicles"; and checkout gains a "Back to results" link that restores the exact prior search/filter state via a `returnTo` query param.
</objective>

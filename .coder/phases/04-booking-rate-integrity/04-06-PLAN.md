<objective>
## Goal
Rebuild the real landing page (`app/page.tsx`) as a complete visual port of `/prototype/landing`'s design — hero photo section, "why us" 3-column grid, vendor list, "Browse by vehicle type" cards — but sourced entirely from real graph data (`searchInventory()`, real `Vendor.provider` names) instead of `app/prototype/mock-data.ts`'s `mockVendors`/`mockVehicleClasses`.

## Purpose
04-05 intentionally scoped `app/page.tsx` to a minimal search-entry form (wiring only), leaving a visual gap the user flagged mid-checkpoint: the real landing page doesn't match the prototype's fuller design. The user explicitly requested a "complete UI build out like the prototype," not a minimal port — this plan closes that gap while keeping data real, which the prototype (mock-data-only) never had to solve.

## Output
- `app/page.tsx` rewritten: hero section (photo background, headline, search form), "why us" grid, real-vendor list, "Browse by vehicle type" grid — all real data.
- `app/landing-hero.tsx`: extracted client component wrapping the existing search form inside the hero section (keeps `app/page.tsx` a server component that can `await searchInventory()`).
</objective>

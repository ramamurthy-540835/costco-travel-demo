<objective>
## Goal
Stand up shadcn/ui as the component library and produce a reviewable, clickable prototype (as real Next.js pages behind a `/prototype` route, not a separate Figma tool) of the three core booking screens — Discovery/Search, Vehicle-Class Detail, Checkout — for user approval before any production UI code (04-01+) is written.

## Purpose
04-01 (discovery/search) and 04-02 (checkout+booking) are UI-heavy vertical slices. Building their real pages against an unapproved design wastes APPLY cycles on rework. This plan produces the approved screen shapes and component set first, so 04-01/04-02's task `<action>` blocks can reference concrete components instead of guessing.

## Output
- shadcn/ui installed and configured (`components.json`, Tailwind v4-compatible setup — this repo is already on Tailwind v4 per 03-01, matching `mastech-agentic-commerce`'s Radix+tailwind-merge pattern but adapted to v4's `@import "tailwindcss"` convention, not v3's `@tailwind` directives)
- A small set of installed shadcn primitives: `button`, `card`, `input`, `select`, `dialog`, `badge` (the minimum set the three prototype screens need — not the full shadcn catalog)
- Three prototype pages under `app/prototype/` (route group excluded from production nav): `search/page.tsx`, `vehicle/[id]/page.tsx`, `checkout/page.tsx` — built against static/mock data (no live graph or Stripe calls; this is a design artifact, not a functional slice)
- `docs/product/04-00-design-prototype.md`: a short PRD-style doc recording what was decided (component choices, screen flow, any deviations from BookCars' UX) for the checkpoint approval record
</objective>

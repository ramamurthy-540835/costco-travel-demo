<objective>
## Goal
Enrich the vehicle-card's data (fuel/powertrain, mileage, cancellation window, deposit, supplier brand accent) and add a supplier/partner checkbox filter to `/search`, backed by two new synthetic ontology fields (`Inventory.fuel_policy`, `Inventory.deposit_amount`, `AddOn.fee_per_day`) and two new graph queries that surface data already loaded but never queried (`VendorPolicy` via `GOVERNED_BY`, `AddOn` via `WAIVES`).

## Purpose
The card and filters currently under-use the ontology: several fetched fields (`negotiatedTerm.included_miles`/`cancellation_window_hours`, `vendor.minimum_rental_days`, `inventory.vehicle_type`) are dropped before render, and two whole node types (`VendorPolicy`, `AddOn`) are loaded into the graph but never queried anywhere in the app. This plan closes that gap and adds the supplier filter BookCars offers, moving the real discovery flow closer to feature parity with the reference platform without inventing UI that isn't backed by real graph data.

## Output
- `Inventory.fuel_policy` / `Inventory.deposit_amount` and `AddOn.fee_per_day` added to seed data and reloaded into the graph.
- `lib/graph/queries.ts` gains `getVendorPolicy`, `getAddOnsCatalog`, `getWaivedAddOnIds`.
- `VehicleCard` shows fuel/powertrain, mileage, cancellation window, deposit chips, and a supplier brand-accent border.
- `/search` gains a supplier/partner checkbox filter, URL-param driven like the existing vehicle-class filter.
</objective>

## AC-1: Vehicle images are real, class-relevant photos
```gherkin
Given VehicleImage currently renders a Car icon on a gradient background
When the image source is swapped to a real vehicle photo
Then each vehicle class renders a photo that actually depicts that class of car (sedan/SUV/hatchback/luxury sedan/minivan — not an arbitrary unrelated stock photo), sourced from a fixed, verified, per-class URL map, with a graceful fallback (e.g. bg color) if the image fails to load
```

**Revision (2026-08-28, checkpoint feedback):** Original AC-1 used `picsum.photos/seed/{id}` — picsum's placeholder photos are arbitrary stock images (Lorem Picsum), unrelated to vehicles, so images looked random and irrelevant. Checked both `mastech-rental-car-management` (no static car-photo assets exist there — BookCars cars are vendor-uploaded at runtime, not shipped in-repo) and this project's own `data/reference/mock-data/*.json` (no image URL fields) — neither had reusable relevant images. Fixed by hardcoding a verified per-`class_name` map of real Wikimedia Commons vehicle photos (via the stable `Special:FilePath` redirect, each URL curl-verified 200 before use):
- Economy → `2024 BYD Seal 06 DM-i.jpg` (sedan)
- SUV → `SUV_Kaiyi_X3.jpg`
- Compact → `Dongfeng Box, Auto 2025, Zurich (20251029-P1074503).jpg` (hatchback)
- Premium → `Audi_A6_C7_Limousine_S_line_quattro_Daytonagrau.JPG` (executive sedan)
- Minivan → `Minivan Los Robles.jpg`

<objective>
## Goal
Stand up a self-hosted Postgres + Apache AGE instance (Docker Compose, mirroring `mastech-agentic-commerce`'s `agent-service/docker-compose.yml` pattern), initialize `rental_graph` with the full schema from Plan 01-01's finalized `graph_schema.sql` (11 domain vlabels + 3 layer-support vlabels/elabels: VocabularyTerm/PARENT_OF/SYNONYM_OF), and load real seed data from `data/reference/mock-data/*.json` and `data/synthetic/*.json` into the graph via an idempotent Python loader.

## Purpose
Plan 01-01 designed the Vocabulary/Taxonomy/Thesaurus/Ontology layers as documents and schema DDL; this plan makes them a real, queryable knowledge graph — the single source of truth Phase 3 (booking/rate integrity) and Phase 4 (add-on integrity) will query against, and the artifact this project's `PROJECT.md` Success Metrics ("Knowledge graph coverage") is measured against.

## Output
- A running Postgres + Apache AGE instance, `rental_graph`, self-sufficient on `docker compose up -d`
- All 12 vlabels and 16 elabels from graph_schema.sql created, with real (not placeholder) seed nodes/edges loaded from the mock/synthetic data files
- A verification script confirming node/edge counts per label and one identity-resolution example each for Member, Vendor, and Reservation
</objective>

<task type="auto">
  <name>Task 2: Connection/agtype helpers + idempotent seed loader from real data files</name>
  <files>graph/requirements.txt, graph/graph_service/__init__.py, graph/graph_service/connection.py, graph/graph_service/agtype.py, graph/graph_service/schema.py, graph/scripts/load_seed_data.py</files>
  <action>
    Create `graph/requirements.txt` with `psycopg[binary]` only.

    Create `graph/graph_service/connection.py` — `get_connection()` reading `PG_HOST`/`PG_PORT` (default 5434)/`PG_DATABASE` (default `rental`)/`PG_USER`/`PG_PASSWORD` (default `localdev`) from env, opening a psycopg3 connection, then issuing `LOAD 'age';` and `SET search_path = ag_catalog, "$user", public;` as two separate `cur.execute()` calls before returning the connection. Every AGE query in this codebase goes through this function.

    Create `graph/graph_service/agtype.py` — `parse_agtype(raw: str) -> dict`, identical technique to agentic-commerce's helper: regex-strip the trailing `::vertex`/`::edge` suffix, `json.loads()` the remainder, raise `ValueError` on mismatch.

    Create `graph/graph_service/schema.py` — `NODE_LABELS` list (all 12 vlabels from graph_schema.sql) and a complete `EDGE_ENDPOINTS` dict covering all 16 elabels, one entry per edge, with direction taken verbatim from ONTOLOGY.md's Relations block for the 14 pre-existing edges and from TAXONOMY.md (`PARENT_OF`) / THESAURUS.md (`SYNONYM_OF`) for the 2 new ones:
    `{"HOLDS_TIER": ("Member","MembershipTier"), "MADE": ("Member","Reservation"), "AT_LOCATION": ("Reservation","Location"), "WITH_VENDOR": ("Reservation","Vendor"), "FOR_INVENTORY": ("Reservation","Inventory"), "INSTANCE_OF": ("Inventory","VehicleClass"), "LOCATED_AT": ("Inventory","Location"), "OFFERED_BY": ("Inventory","Vendor"), "GOVERNED_BY": ("Vendor","VendorPolicy"), "ELIGIBLE_FOR": ("MembershipTier","NegotiatedTerm"), "OFFERS_TERM": ("Vendor","NegotiatedTerm"), "INCLUDES_PERK": ("NegotiatedTerm","Perk"), "WAIVES": ("Perk","AddOn"), "REQUESTED": ("Reservation","AddOn"), "PARENT_OF": ("VehicleClass","VehicleClass"), "SYNONYM_OF": ("VocabularyTerm","VehicleClass")}`.
    Do not defer any of these 16 to "read from ONTOLOGY.md at runtime" — hardcode the full dict, matching the standard the reference plan (commerce 01-01's `schema.py`) held itself to.

    Create `graph/scripts/load_seed_data.py`:
    - Reads each source JSON file listed in this plan's Source Data context.
    - Wipes `rental_graph` (`MATCH (n) DETACH DELETE n`) before loading, matching agentic-commerce's `reset_and_seed_sample_graph` idempotency pattern — commit the wipe before creating anything.
    - For each row in each file, `MERGE` (not `CREATE`) the corresponding node using its natural key, per this explicit mapping (confirm each field name against the actual source JSON before coding): `{Member: member_id, Vendor: provider, VehicleClass: class_name (or vehicle_class field name as it appears in rental_inventory_500.json), Inventory: rental_id, Location: city, Reservation: reservation_id, MembershipTier: tier_id, NegotiatedTerm: term_id, Perk: perk_id, AddOn: addon_id, VendorPolicy: <the vendor_policies.json id field — confirm exact name>}`. `VocabularyTerm` has no real seed data in this phase (see Task 3 note) and is not MERGEd here. Bind every value via the `%s::agtype` + `json.dumps(...)` parameter-binding pattern (never string-interpolate a Cypher value) — `MERGE` makes a second run idempotent without relying solely on the wipe step.
    - After all nodes are committed, create the 16 edges from ONTOLOGY.md's Relations block by `MATCH`-ing both endpoints on their natural keys and `MERGE`-ing the edge — including the new `PARENT_OF` (VehicleClass groupings from TAXONOMY.md) and `SYNONYM_OF` (thesaurus placeholder entries from THESAURUS.md, if any are marked as real rather than illustrative-only) edges.
    - Print a per-label row count as it loads.
  </action>
  <verify>Run `python graph/scripts/load_seed_data.py` twice in a row — both runs exit 0 with identical printed counts (proves the wipe-then-merge is idempotent; duplicate-freedom confirmed by Task 3's verify_graph.py).</verify>
